# Scale Budget — 项目规模预算

宪法 Rule 12 的执行细则。所有阈值都是硬性指标，命中即触发对应动作。

## 硬性上限

| 指标 | 上限 | 适用 |
| --- | --- | --- |
| 单文件 | 300 行 | 所有源码与测试文件（.rs / .swift） |
| 逻辑模块 | 1,200 行 | 单一职责模块（buffer、selection、undo、layout…） |
| Rust Core 总量 | 20,000 行 | `core/src`（不含测试） |
| Swift App 总量 | 5,000 行 | `app/`（不含生成代码与测试） |
| 项目总量 | 25,000 行 | 上两项合计 |

测试与文档不计入预算，但测试文件同样受 300 行/文件限制。

## 上帝文件禁令

文件必须能用一句话概括单一职责。命中任一即违规：

- 超过 300 行；
- 职责超过一个（例如同时管理 Buffer 与 Layout）；
- 依赖范围超出本模块应有边界。

## 预警与扩容

- **预警线：** 总量达到预算 80%（Core 16,000 / 总 20,000）→ 触发精简审计。
- **扩容条件（全部满足才允许）：**
  1. 新功能无法在现有预算内以合理方式实现；
  2. 已先回答"能否通过精简 / 合并实现？"且答案是否；
  3. 有 ADR 记录，且经用户确认；
  4. 单次扩容 ≤ 当前预算 25%；
  5. 扩容 ADR 说明抵消的精简；若无，必须给出理由。
- **禁止：** 用扩容掩盖架构问题；扩容不能替代精简。

## 精简触发条件（任一命中即触发）

1. 总量达到预警线（80%）。
2. 单文件 / 模块被反复改动（高 churn）。
3. 重复模式出现 ≥ 3 处（Rule of Three → 提取或复用）。
4. 连续 2 个 PR 的复杂度预算三问出现"永久复杂度"且无对应收益。
5. 修改一个切片导致大量无关测试改动。

## 重构与封装时机

- **常规重构：** 每次 Red → Green → Refactor 的第三阶段（宪法 Rule 5）。
- **封装时机：** 内部实现要变化（如 String → Rope）或出现跨模块耦合时才封装；封装必须最小化（Rule 1：无证明的抽象层禁止）。
- **接口暴露：** 公共 API 必须先 ADR（Rule 4）；默认 `private` / `pub(crate)`，只有跨模块协作需要才提升可见性，并在注释中写明理由（Rule 10）。无消费者的公共 API 禁止交付（Rule 14）：新接口必须与真实调用方同切片交付；既有无消费者接口在接线切片或精简审计中处置。
- **隐藏内部实现：** Rust 默认私有；任何 `pub` 都是决策，进入 ADR 审计。

## 删除冗余

- 死代码立即删除（审计或编译警告发现即处理）。
- 未兑现的抽象（YAGNI）在精简审计中撤销，对应 ADR 标注 Superseded 或回滚。
