# ADR-009 — Layout 逻辑行模型

- **Status:** Accepted
- **Date:** 2026-08-02
- **Version:** 1.0
- **新增 Public API:** 1 个类型 + 4 个方法
- **影响模块:** Core（新增 layout 模块）
- **是否违反 Single Responsibility:** 否
- **是否增加循环依赖:** 否

---

## 决策

`Layout` 是不可变逻辑行索引：`build(text)` 一次性扫描（O(n)）得到行起点 `Vec<usize>`，提供行数、行字节区间、偏移→行号三个查询。**编辑后必须重建**（调用方职责，T-007 / T-013 封装）。

## 原因

- ADR-006 修订：String 存储下编辑本身 O(n)，行索引不改变渐近复杂度。
- **不可变快照比脏标记缓存更简单**：无脏状态、无失效 bug；代价是编辑后重建，由调用方显式完成。
- `\n` 是唯一行分隔符；`\r` 暂视为行内容（CRLF 归一化留给文件模型切片）。
- 视觉 / 像素布局（字体度量、shaping、软换行）属于 T-012（Metal 渲染），不在本模块——保持 Core 平台无关（ADR）。
- 软换行默认关闭（ADR-019）：Layout 只表达逻辑行，视觉折行属 App 渲染层。

## 审计

### Single Responsibility — 否（不违反）

Layout 只回答"行结构"（行号 ↔ 字节区间 ↔ 偏移）；不持有文本、不负责像素坐标。

### 循环依赖 — 否（不违反）

layout 模块不依赖其他模块，Core 内独立。

## 新增 Public API

| API | 职责 |
| --- | --- |
| `Layout::build(text: &str) -> Layout` | 从文本快照构建行索引，O(n) |
| `line_count() -> usize` | 行数（空文本为 1 行） |
| `line_range(line) -> Option<Range<usize>>` | 行号 → 字节区间（不含 `\n`） |
| `line_at(offset) -> Option<usize>` | 字节偏移 → 行号；越界返回 `None` |

## 影响模块

- **Core（新增 layout 模块）** — 唯一影响；T-012 渲染切片基于本模块的字节区间做视觉布局。

## 复杂度预算（宪法 Rule 9）

1. **增加了哪些复杂度？** 1 个模块、0 抽象层、1 个 `Vec<usize>`。
2. **是否是永久性的？** 逻辑行接口是永久结构；`Vec` 实现随 Rope 替换（T-020），接口不变。
3. **有没有更简单但同样满足需求的方案？** 无——无缓存方案在滚动/选区场景退化，树索引在 String 下无收益。

结论：1 模块 / 1 类型 / 4 方法。

## 备注

- 替换触发点：T-020 基准证明 String 不达标时，行索引随存储结构一起替换，公共 API 不变。
- CRLF 归一化、视觉坐标均不在本 ADR 范围；软换行的视觉行映射见 ADR-019
  （Core 边界不变：Layout 仍是逻辑行）。
