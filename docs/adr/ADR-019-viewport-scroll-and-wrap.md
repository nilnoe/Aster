# ADR-019 — 视口滚动与软换行（水平滚动 v1 + 软换行用户可选）

- **Status:** Accepted
- **Date:** 2026-08-02
- **Version:** 1.0
- **新增 Public API:** 0（视口滚动与换行是 App 视图层状态；Core 不变）
- **影响模块:** roadmap、app/（视口 / 渲染）；core/ 不变（ADR-009 边界确认）
- **是否违反 Single Responsibility:** 否
- **是否增加循环依赖:** 否

---

## 决策

1. **水平滚动是 v1 默认能力**（ADR-006 原方案落地）：`scrollX` 点值，触控板双指
   平移 / Shift+滚轮平移；光标移出右边缘时横向滚到可见；内容宽度按**可见行**
   最大宽度计算（不取全文档最宽行——最小化，超长行场景后续再调）。
2. **软换行是用户可选视图模式，默认关闭**：默认行为 = 按行渲染 + 水平滚动
   （ADR-006 既定）；开启后长行在视口宽度处视觉折行。
3. **软换行不改变 Core**：`Layout`（ADR-009）仍是逻辑行；视觉行（折行后的显示
   行）映射是 App 渲染层的职责（Core 平台无关，ADR 总纲 3.3）。Core 只提供逻辑行
   字节区间，折行位置由渲染层按字体度量计算（LineLayout 已有 shaping 数据）。
4. **开启机制**：经配置系统（ADR 总纲 Layer 2 Config DSL / Layer 3 Lua）开启；
   配置系统落地前，视图层以默认关闭的常量开关实现，不暴露 UI
   （Rule 9：不为临时开关引入 UI 状态）。

## 原因

- **水平滚动是既定决策的落地**：ADR-006 原方案就是「按行渲染 + 水平滚动」；当前
  长行直接截断且无法平移，是计划与实现之间的缺口（用户反馈确认），必须补齐。
- **软换行从「v1 不做」变为「默认关闭的可选项」**：默认体验不变（ADR-006 精神），
  但把能力做成可选项，满足用户对长行阅读的实际需求；默认关闭时几乎零复杂度
  （Rule 9）。
- **视觉折行放 App 层**：Core 保持平台无关（ADR 总纲 3.3）；字体度量已在 App
  （LineLayout），折行是纯渲染层映射，不引入 Core 改动。

## 审计

### Single Responsibility

视口状态（scrollX / wrapEnabled）只属于 App 视图层；Core 不新增行/列视觉语义。

### 循环依赖

无新依赖方向；App → Bridge → Core 不变。

## 新增 Public API

无。`scrollX` / `wrapEnabled` 是视图层内部状态；软换行的视觉行映射不暴露为
Core 公共接口（Rule 4 不触发）。

## 影响模块

- **roadmap** — 新增 T-018（水平滚动）、T-019（软换行）；Phase 3~5 重新编号。
- **app/** — T-018：视口 `scrollX` + 横向平移输入 + 光标横向可见性；
  T-019：视觉折行映射（仅开启时生效）。
- **core/** — 不变（ADR-009 逻辑行边界确认）。

## 复杂度预算（宪法 Rule 9）

1. **增加了哪些复杂度？** T-018：1 个视口状态 + 输入平移 + 光标可见性；
   T-019：视觉折行映射（默认关闭，不改变默认路径）。
2. **是否是永久性的？** 水平滚动是 v1 永久能力；软换行是长期可选项（默认关闭）。
3. **有没有更简单但同样满足需求的方案？** 只做水平滚动、永远不做软换行——无法
   满足长行阅读需求；软换行默认开启——反转 ADR-006 且改变默认体验，被拒。
   用户可选 + 默认关是「两全」的最简形态。

结论：0 模块 / 0 API / 2 个视图层状态，未触及红线。

## 备注

- 软换行的视觉列映射（光标在折行间移动、Up/Down 视觉列保持）在 T-019 细化。
- 水平滚动与平滑滚动（T-022）独立：T-018 先做点值平移，动画随平滑滚动切片。
