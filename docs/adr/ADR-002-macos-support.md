# ADR-002 — macOS 支持策略（Latest Only）

- **Status:** Accepted
- **Date:** 2026-08-02
- **Version:** 1.0
- **新增 Public API:** 0 个
- **影响模块:** Swift App、Metal Rendering、系统集成
- **是否违反 Single Responsibility:** 否
- **是否增加循环依赖:** 否

---

## 决策

本项目只支持最新版 macOS，不做任何旧版本兼容。最低支持版本 = 当前最新稳定版（每个发布周期确定）。

## 原因

- 一切为了目标用户的体验：直接使用最新 Metal、最新 AppKit API、Swift 并发等新能力，不为旧系统保留条件分支、降级路径或兼容层。
- 兼容性是永久复杂度（宪法 Rule 9），且服务于一个本项目的非目标人群。
- 与"不做跨平台"决策同构：跨平台被拒绝的理由，同样适用于跨版本兼容。
- 复用优先（宪法 Rule 11）+ 使用系统能力（ADR Principle 4）：最新系统能力直接可用，不重复造轮子。

## 审计

### Single Responsibility — 否（不违反）

本 ADR 是支持策略，不引入模块，无职责混入。

### 循环依赖 — 否（不违反）

无新增依赖方向。

## 新增 Public API

无。

## 影响模块

- **Swift App** — 可直接使用最新 AppKit / Swift 能力。
- **Metal Rendering** — 可使用当前世代特性（Metal 3）。
- **Core** — 不受影响，保持平台无关。

## 复杂度预算（宪法 Rule 9）

1. **增加了哪些复杂度？** 无新增模块 / API；取消兼容路径后复杂度下降。
2. **是否是永久性的？** 是——本策略永久有效，随 macOS 更新滚动。
3. **有没有更简单但同样满足需求的方案？** 无——"不做兼容"就是最简单方案。

结论：0 模块 / 0 API / 0 抽象层。

## 备注

- 每个发布周期记录当时的"最新 macOS 版本"于 Changelog 与 benchmarks 环境说明。
- 测试只在目标版本上运行。
