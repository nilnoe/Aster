# ADR-003 — 插件安全模型（Trusted by Default）

- **Status:** Accepted
- **Date:** 2026-08-02
- **Version:** 1.0
- **新增 Public API:** 0 个
- **影响模块:** Plugin Runtime（Lua）、Plugin API
- **是否违反 Single Responsibility:** 否
- **是否增加循环依赖:** 否

---

## 决策

插件默认被信任：Lua 插件以用户身份运行，第一阶段不提供沙箱。

用户对自己安装的插件负责；从不可信来源获取插件属于用户决策。

## 原因

- 沙箱会显著增加 Plugin API 与 Runtime 复杂度（进程隔离、权限模型、数据通道），违背第一版最小化目标（宪法 Rule 9）。
- 目标用户是技术用户（会写 Lua），与"高度可编程"哲学一致。
- 若未来开放第三方插件分发，再引入签名与沙箱（记为后续 ADR 候选）。

## 审计

### Single Responsibility — 否（不违反）

信任模型是安全策略，不引入模块。

### 循环依赖 — 否（不违反）

无新增依赖方向。

## 新增 Public API

无。

## 影响模块

- **Plugin Runtime（Lua）** — 不因沙箱增加隔离层。
- **Plugin API** — 保持直接、同步、无权限层。

## 复杂度预算（宪法 Rule 9）

1. **增加了哪些复杂度？** 0 模块 / 0 API / 0 抽象层；沙箱复杂度被推迟而非引入。
2. **是否是永久性的？** 否——该决策只覆盖第一阶段；开放插件分发时必须重估。
3. **有没有更简单但同样满足需求的方案？** 沙箱即备选，但其成本远超当前收益。

## 备注

- PTY 内容始终视为不可信数据，不作为代码执行来源（除非用户显式 source）。
- 引入"插件市场 / 远程插件"时，本决策自动进入重估。
